Голосовые уведомления Трайтэк
Проект написан с нуля на HTML, CSS и JavaScript.

Запуск на Windows
1. Установите Python и проверьте команды python и ssh.
2. Распакуйте весь архив. В папке Сайт запустите start_practice.bat двойным щелчком.
3. В окне SSH введите пароль сервера, если он запрошен. Оставьте окна SSH и HTTP-сервера открытыми.
4. Сайт откроется по адресу http://127.0.0.1:8765/. Если окна уже запущены, используйте существующий экземпляр: повторный запуск может конфликтовать с занятыми портами.

Работа
Добавьте абонентов вручную либо импортируйте CSV UTF-8.
Обязательные столбцы: name;account;phone;balance. Дополнительный столбец: address.
Полный заголовок: name;address;account;phone;balance.
Импорт дополняет список; одинаковые записи допускаются.
Выберите клиентов, измените шаблон {name}, {address}, {account}, {balance}, проверьте персональные сообщения.
Для одного клиента нажмите «Тестовый звонок · имитация», затем «Ответить».
Для группы нажмите «Запустить демонстрацию для выбранных» и скачайте WAV.
Реальные номера не набираются. Список и шаблон хранятся в localStorage данного браузерного профиля; резервная копия списка — экспорт CSV.

Сервер
Основной API на Ubuntu: http://127.0.0.1:8020/; доступ сайта через SSH-туннель на локальный порт 18020.
SSH: порт 2222. start_practice.bat содержит адрес исходного домашнего сервера; на другом стенде измените параметры.
TTS: Qwen3-TTS 0.6B CustomVoice Q8_0, голос Serena, RX 580 / Vulkan / qwentts.cpp.
Служба qwen3-tts включена для автоматического старта. Модель загружается заново при каждом запросе.
Контейнер practice-qwen:vulkan использует /dev/dri, группы render/video, лимит четырёх CPU и 6 ГБ RAM.
В server находятся действующий GPU API, прежний CPU API, настройки службы и скрипт переключения.
Для переноса нужны отдельно установленный Docker, Vulkan, runtime и два GGUF-файла; один архив сайта не разворачивает модель автоматически.
Веса модели, Docker-образ, виртуальное окружение и SSH-ключи в архив не входят.

Замеры
CPU API: 41,15 с (2 потока), 39,06 с (4 потока).
GPU API Serena: среднее 6,27 с при трёх запросах после прогрева; WAV 9,04 с.
Это сравнение двух реализаций: изменены устройство, runtime и формат весов; не только число потоков.
Отдельные CLI-сравнения CPU/GPU сохранены в Замеры TTS, вместе с исходными условиями, WAV и журналами.
Проверка сайта 2 октября: один запрос через внешнюю сеть, 8,07 с до полного ответа; воспроизведение подтверждено.
Новая проверенная запись test_call_NEW.wav сохранена после исправления пустого локального файла; результаты её проверки отдельные.
